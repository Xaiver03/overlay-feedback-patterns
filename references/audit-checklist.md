# 现状审计与整改清单

用于把这份规范落到一个已有产品上。**先取基线，再选一档做完**，不要一次改全仓。

## 1. 基线探针

在仓库根跑（按本仓实际目录调整 `src/`）。每条都要留**读数**，不要只看有没有。

```sh
# 用了哪些浮层原语（判断底座：Radix / antd / MUI / 自绘）
rg -o "@radix-ui/react-(dialog|alert-dialog|popover|tooltip|dropdown-menu|toast|visually-hidden)" -g'*.{ts,tsx,js,jsx}' | sort | uniq -c
rg -l "from ['\"](antd|@mui/material|@mui/base|element-plus|vant|antd-mobile)" -g'*.{ts,tsx}' | wc -l

# 模态类使用规模
rg -c "<(Dialog|Modal|AlertDialog|Sheet|Drawer|Popover|Tooltip)[ >]" -g'*.tsx' | sort -t: -k2 -rn | head -20

# 移动端底部面板：是真 sheet 还是「Sheet 组件摆到底部」
rg -n "side=[\"']bottom[\"']|Snap|vaul|detent|snapPoint|bottom-sheet|BottomSheet" -g'*.tsx'

# 轻反馈有几套（>1 套即为债务：时长/位置/堆叠规则会互相冲突）
rg -o "from ['\"][^'\"]*(toast|sonner|use-message|notification)['\"]" -g'*.{ts,tsx}' | sort | uniq -c

# 浏览器原生对话框 —— 危险操作未收敛的直接证据，应为 0
rg -n "(^|[^.\w])(confirm|alert)\s*\(" -g'*.{ts,tsx,js,jsx}' -g'!*test*'

# 关闭策略有没有约定 —— 全为 0 说明所有浮层都在吃库默认值
rg -c "onEscapeKeyDown|onInteractOutside|onPointerDownOutside|closeOnOverlayClick|disableEscapeKeyDown|maskClosable|modal=\{false\}" -g'*.tsx'

# 自动消失时长有没有被局部乱覆盖
rg -o "duration:\s*[0-9]+" -g'*.{ts,tsx}' | sort | uniq -c | sort -rn

# 撤销能力有没有（action/undo 只用于「重试/跳转」而不用于撤销 = 没有）
rg -n "undo|revert|restore|deleted_at|deletedAt|softDelete|soft_delete|recycle|trash" -g'*.{ts,tsx}' | head -30

# 行内报错有没有统一封装
rg -c "FormMessage|formMessage|aria-invalid|role=\"alert\"" -g'*.tsx'

# 层级有没有约定（自绘 inset-0 = 绕过焦点陷阱/滚动锁/inert 的债务）
rg -c "z-\[?[0-9]+" -g'*.tsx'; rg -n "fixed inset-0" -g'*.tsx' | wc -l
```

## 3. 整改分档（一档 = 一个可验证纵切）

按「收益 ÷ 风险」排序。**只做你选中的那一档，做完验证再谈下一档。**

| 档 | 内容 | 风险 | 可机械化验证 |
|---|---|---|---|
| **T1 清原生对话框** | 全部 `confirm()`/`alert()` 收敛到统一危险入口 | 低（纯替换，行为等价或更好） | `rg` 计数归零 + 契约测试 |
| **T2 统一危险入口** | 建 `resolveDangerTier()` + `useDangerConfirm()`，AlertDialog 默认禁 scrim、初始焦点在取消、主按钮 destructive | 低 | 单测：三档判定、Esc 走取消分支 |
| **T3 轻反馈归一** | 两套 toast 合成一套，时长/位置/堆叠/去重集中配置，禁局部 `duration` 覆盖 | 中（要过全部调用点） | lint 规则或 rg 计数：`duration:` 只出现在配置处 |
| **T4 行内报错归位** | 提交失败的字段级错误从 toast 改为字段下方常驻 + 顶部汇总 + 滚动聚焦第一个错误 | 中（改表单流程） | 契约测试：错误存在期间不消失 |
| **T5 关闭策略显式化** | 每个浮层组件按矩阵设 `onEscapeKeyDown`/`onInteractOutside`；已脏表单关闭前确认；强制阅读禁关 | 中 | 契约测试逐类断言 |
| **T6 撤销链路** | 有软删除的删除改 Snackbar+撤销（先核 §2 的 7 条前提，缺则回 T2 并记录为「产品决策」） | **高**（涉数据模型与审计） | 端到端：删→撤→数据回来→留痕两条 |
| **T7 移动端形态** | 居中 Dialog 按视口切底部 sheet；引入分档（30/60/80）+ 把手 + 返回键接管 | 中高（视觉面大） | 真机/模拟器走查 + 截图 |
| **T8 层级与自绘收敛** | `z-*` 换档位 token；`fixed inset-0` 自绘层迁到统一原语 | 低中 | rg 计数 + 视觉回归 |

**T6 是唯一可能推翻前面判断的一档**：撤销要求后端有软删除、幂等、审计留痕，且动作没有外部副作用。任何一条不满足，正确结论是「这一格不配用撤销，保留确认框」，并把它作为产品决策记录，而不是硬做 UI。

## 4. 多端核对

同一句话在四个端都要有落点，缺端要显式记录：

| 能力 | Web 桌面 | Web 移动/套壳 | 小程序 | 原生壳 |
|---|---|---|---|---|
| hover 类（Tooltip/Hover Card） | 可用 | **必须有替代**（长按/常驻/详情内） | **无原生**，需替代 | 无 |
| 键盘（Esc / ⌘K / Tab 陷阱） | 必须支持 | 无实体键盘场景降级 | 不适用 | 外接键盘要支持 |
| 系统返回 | 浏览器返回 | **必须接管**（关浮层优先于退页） | 页面栈 | 返回键/侧滑 |
| 危险确认 | AlertDialog | AlertDialog（别用原生 `confirm()`） | 自绘 Modal（`wx.showModal` 放不下后果说明） | 原生 alert 可，但要本地化 |
| 撤销 Snackbar | 左下/右下 | 底部拇指区 | 自绘（`showToast` 不支持动作） | 同 Web 移动 |
| 底部面板分档 | 不用 | vaul/自绘分档 | `page-container` 或自绘 | `UISheetPresentationController` / `ModalBottomSheet` |

## 5. 评审清单（改完逐条打勾）

**选型**
- [ ] 每条反馈都能说出它属于哪一级（0–5），且没有更低的级别能解决它
- [ ] 没有「用 toast 承载必须看到的错误」
- [ ] 没有 Modal 套 Modal；同屏最多一个第 5 级层
- [ ] 高频可撤销操作没有确认框
- [ ] 不可逆/涉资金/对外可见的动作有重档确认

**关闭与时长**
- [ ] 危险确认不响应 scrim、不给 X、Esc = 取消
- [ ] 已脏表单的 scrim/Esc/返回都会先问「放弃修改」
- [ ] 强制阅读类（协议、告知）不可点背景关闭
- [ ] 行内报错永不自消，直到字段被改动
- [ ] 带动作的提示 ≥7s 且 hover/聚焦暂停
- [ ] 同屏轻反馈有上限、同类有合并去重

**危险操作**
- [ ] 标题写后果、正文写范围、主按钮复述动词且用 destructive 样式
- [ ] 初始焦点在取消
- [ ] 档位由一个判定函数决定，不是各页自判
- [ ] 承诺了撤销的地方，撤销真的可执行且留痕
- [ ] 无原生 `confirm()`/`alert()` 残留

**移动端**
- [ ] 从属任务用 Bottom Sheet 而不是窄屏 Drawer / 居中弹窗
- [ ] Sheet 有把手、至少两档、可拖回、记忆档位
- [ ] 键盘弹起不埋住主操作按钮；提交错误不被键盘遮挡
- [ ] 系统返回/侧滑能关浮层
- [ ] hover-only 的信息都有替代通道

**无障碍**
- [ ] 模态有可访问名称、焦点陷阱、关闭归还焦点、背景 `inert`
- [ ] 轻反馈 `role=status`/`aria-live=polite`；错误字段 `aria-invalid` + `aria-describedby`
- [ ] 严重度不只靠颜色
- [ ] 触屏目标 ≥44pt
- [ ] 全部动作可纯键盘完成

## 6. 适配层落点约定（多产品场景）

一个负责人有多个仓库时，**通用判据只住在本 Skill 一处**，每个仓库只允许有一份自己的适配层：

- 落点：该仓 `docs/` 下与既有设计文档并列的位置，命名沿用该仓惯例（`overlay-feedback-adaptation.md` 是默认建议名）。
- 内容：只有 §1 现状基线（带可复现探针命令 + 现量日期）、§2 本仓有什么/缺什么、§3 本仓危险档位与撤销档成不成立、§4 本仓 T1–T8 影响面、§5 本仓的端、§6 已有资产。**不复制通用判据**。
- 顶部必须有真源指针（本 Skill 名 + 权威路径），并写明「与通用规则冲突时以通用规则为准，然后回来改本仓适配层」。
- 同一仓库的多个 UI 面若代码不共享（例如 Web 主客户端 vs 小程序 vs 静态文档站），各面单独取读数，可以另起一份 `*-surfaces.md`，但要互相指认，别让读数被当成同一分母。
- **不要在通用 Skill 里登记各仓适配层的路径清单**——那是一份会随仓库增删而漂的抄件。要索引就在负责人自己的记忆里现量。
- 写完必须核两件事：该仓 `.gitignore` 是否把新文档挡住（有些仓用 `docs/*` + 逐文件白名单，新文档会静默不进版本控制）；该仓是否有别的会话在飞（`git status` 里的 `M` 不是本次改动，别顺手提交）。

## 7. 基线读数的三个可信度陷阱

1. **`package.json` 里有库 ≠ 在用这个库。** 按 import 计数，不按依赖声明计数（实测有仓库声明 11 个 Radix 包而 9 个零引用，也有仓库的「组件库」只活在孤儿组件里）。
2. **计数会漂 ±1。** 并发会话在改文件、glob 是否排除测试/兜底包装，都会让同一探针两次读数不同。所以读数必须配一条可重跑的命令，并写明「引用前先重跑」；把某个具体数字当永久事实写进正文就是错的。
3. **兜底实现不该计入缺陷。** 例如统一确认组件里那处刻意的 `window.confirm` 降级、或原生适配层的兜底分支——分母要显式说明排除了什么，否则同一仓会得出两个都「对」的数。

## 8. 别做的事

- 别为了「规范统一」把所有提示都改成同一种（那是把 5 级压成 1 级，一定会变差）。
- 别在文档里定档位阈值而代码里各页自判 —— 规则要落在一个可被调用的判定函数上。
- 别把「撤销」当纯 UI 改动做，先核 §3 T6 的七条前提。
- 别用一次性大改覆盖多个档；一档一个纵切，每档留读数。
- 别把项目专属的组件名、token、目录结构写进这份全局规范 —— 它们属于该仓库自己的适配层。
