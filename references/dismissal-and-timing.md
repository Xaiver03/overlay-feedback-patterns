# 关闭策略、时长、堆叠与无障碍

## 1. 关闭策略矩阵

「怎么关掉」是浮层最容易做错、也最容易被代码里零约定地放过去的一格。**默认值不等于约定**：Radix/MUI 的 Dialog 默认点背景就关，如果这个弹窗里有未保存内容，那这个默认值就是缺陷。

图例：✓ 允许 · ✗ 禁止 · (c) 条件允许 · — 不适用

| 类型 | 点背景 scrim | Esc | 自动消失 | 显式关闭按钮 | 系统返回键/手势（移动） |
|---|---|---|---|---|---|
| Tooltip | 移开即消 | ✓ 立即隐藏 | ✓ | ✗ | — |
| Hover Card | ✓ | ✓ | ✗ | ✗ | — |
| Popover | ✓ | ✓ | ✗ | ✗ | ✓ |
| Menu | ✓ | ✓ | ✗ | ✗ | ✓ |
| Toast | ✗ | ✓ 可关 | **✓ 4–8s** | 可选 | ✓ |
| Snackbar（带动作） | ✗ | ✓ 视为已读 | ✓ **≥7s**，hover/聚焦暂停 | ✗ | ✓ |
| Notification | ✗ | ✓ | ✗ 或 ≥10s | **✓ 必须有** | — |
| Alert（页面内） | — | — | **✗** | 可关的要记状态 | — |
| Inline Alert | — | — | **✗ 永不自消** | ✗ | — |
| Banner | — | — | ✗ | ✓ 关闭后持久化 | — |
| Modal（只读/无改动） | ✓ | ✓ | ✗ | ✓ | ✓ |
| Modal（有未保存改动） | (c) 先问「放弃修改？」 | (c) 同左 | ✗ | ✓ | (c) 同左 |
| Modal（强制阅读：协议/告知） | **✗** | **✗** | ✗ | 只有「同意/不同意」 | ✗ |
| **AlertDialog（危险确认）** | **✗** | ✓ **= 取消** | ✗ | **✗ 不给 X** | ✓ = 取消 |
| Popconfirm | ✓ = 取消 | ✓ = 取消 | ✗ | ✗ | ✓ = 取消 |
| Drawer | ✓ | ✓ | ✗ | ✓ | ✓ |
| Bottom Sheet | ✓ | — | ✗ | ✓ 把手/关闭 | ✓ |
| Full-screen Overlay | — | ✓ | ✗ | ✓ 常驻 | ✓ |
| Command（⌘K） | ✓ | ✓ 直退 | ✗ | ✗ | — |

### 三条不变量

1. **Esc = 取消 = 安全侧。** Esc 在任何浮层里都不得触发确认、保存、提交、扣款、删除。实现上：危险确认的 `AlertDialogAction` 不能绑 Esc；Radix 的 `onEscapeKeyDown` 默认走 dismiss，要确认 dismiss 落在取消分支。
2. **scrim 关闭 = 丢弃。** 只有「无未保存内容」或「丢弃无代价」才允许。已脏表单、危险确认、强制阅读三类必须显式关掉 `onInteractOutside`/`onPointerDownOutside`。
3. **关闭必须有归属。** 背景滚动锁定、焦点陷阱、关闭后焦点归还触发元素，三者要么齐全要么别做模态。半套（锁了滚动没还焦点）比不做更糟。

## 2. 时长与自动消失

判据只有一条：**这条信息错过会不会造成损失？**

| 情形 | 时长 | 说明 |
|---|---|---|
| 成功回执（Toast） | 4s | 「已保存」 |
| 失败回执（Toast） | 6–8s | 失败要给人读完的时间；若失败原因需要被读到并修正 → 改 Inline Alert/Alert |
| 带动作的提示（Snackbar） | ≥7s | **hover / 键盘聚焦时暂停计时**；动作在计时结束前始终可点 |
| 需要行动的提示 | 不自消 | 一旦消息里有「请…」，它就不该消失 |
| 行内校验错误 | **永不自消** | 直到该字段被改动并重新校验 |
| 页面级 Alert / Banner | 不自消 | 状态消失才消失 |
| 模态类 | 不自消 | 自动关闭模态是 bug |

补充规则：
- 进度类反馈没有「时长」，但有**最小可见时长**：不足 ~300ms 的操作不要闪出浮层（用延迟渲染），否则会闪烁。
- 上传/导出这类长任务：Toast 只报「已开始」，结果走 Notification 或任务中心，不要靠一条 8 秒提示承载完成状态。

## 3. 堆叠、去重与并发

- 同屏轻反馈：桌面 ≤3、移动 ≤2，超出即合并/淘汰最旧。
- **同类去重并计数**：连续 3 次同一失败 → 一条「3 条记录保存失败」，不是 3 条相同文案。
- 同一时刻**只允许一个第 5 级模态层**。第二层出现会让焦点、滚动锁、Esc 归属全部失控；需要承接第二层信息就降级到第 3/4 级就地提示。
- 优先级：Inline Alert > 区域 Alert > 页面 Banner > Snackbar > Toast。能在低层说清就别飘到全局。
- 页面切换时清掉所有可错过层（Toast/Snackbar）；模态与就地错误按各自语义处理。

## 4. 无障碍与工程要点（逐条可测）

| 项 | 要求 | 怎么验 |
|---|---|---|
| 语义 | 模态 `role=dialog`/`alertdialog` + `aria-modal=true`；轻反馈 `role=status`；需立即知晓的错误 `role=alert` | DOM 回读 |
| 标题 | 模态必须有可访问名称（`aria-labelledby` 指到标题） | DOM 回读 |
| 焦点 | 打开进浮层、关闭回触发元素；危险确认**初始焦点在取消** | 键盘走查 |
| 焦点陷阱 | 模态内 Tab 循环不外逃 | 键盘走查 |
| 背景 | 模态期间背景内容 `inert`/`aria-hidden`，避免读屏器读到两层 | DOM 回读 |
| 播报 | Toast 用 `aria-live=polite`；`assertive` 只留给真正紧急且少用的错误（会打断） | 读屏器抽验 |
| 颜色 | 严重度不能只靠颜色区分，必须配图标或文字 | 视觉走查 |
| 触屏 | 目标 ≥44×44pt；Tooltip/Hover Card 的信息在触屏上必须有常驻或点击替代 | 真机走查 |
| 动效 | 尊重 `prefers-reduced-motion`；进出时长见动效规范，本 Skill 不定 | 系统设置切换 |
| 键盘 | 所有浮层的动作都能用键盘完成，包括危险确认 | 纯键盘走查 |

## 5. 层级与 z-index

- 用**档位**而不是随手写 `z-50`：底 → 顶建议 抽屉/Sheet < 模态 < 危险确认 < 轻反馈 < 全局加载遮罩。轻反馈必须浮在模态之上（模态里触发的保存结果要看得见）。
- 同一档位内按出现时间叠。
- 自绘 `fixed inset-0` 覆盖层是债务：它绕过焦点陷阱、滚动锁、Esc 与 `inert`，应逐步收敛到统一浮层原语。
