# 中英对照与提示词模板

「加个弹窗」是最贵的一句需求话 —— 它把 18 种选择压成 1 种，实现者只能猜。这一页给的是**能直接粘贴的精确说法**。

## 1. 对照表

| 英文（组件库真名） | 规范中文名 | 日常/口语叫法 | 别叫 | 一句话区分 |
|---|---|---|---|---|
| Tooltip | 文字提示 | 气泡提示、鼠标悬停提示 | 弹窗 | 只有文字，不可点，hover 才有 |
| Hover Card | 悬停卡片 | 悬浮卡 | 气泡 | hover 出现的富文本预览 |
| Popover | 气泡卡片 | 浮层、气泡 | 弹窗 | 锚定控件的轻内容，不阻塞 |
| Menu / Dropdown Menu | 菜单 / 下拉菜单 | 下拉 | 气泡 | 一组动作，选即关 |
| Modal / Dialog | 模态弹窗 / 对话框 | 弹窗 | 遮罩 | 一个独立子任务 |
| AlertDialog | 确认型模态 / 警告对话框 | 危险弹窗、二次确认框 | 提示框 | 必须表态，不给点背景关闭 |
| Popconfirm | 气泡确认框 | 小确认、就地确认 | 弹窗 | 锚在按钮上的轻量确认 |
| Drawer / Side Sheet | 侧边抽屉 / 侧边面板 | 抽屉、侧滑 | 弹窗 | 从边缘滑入的从属面板 |
| Bottom Sheet | 底部面板 / 半屏弹层 | 半屏、底部弹层、sheet | 抽屉 | 底部升起、可拖拽换档 |
| Full-screen Overlay | 全屏浮层 | 遮罩页、全屏页 | 弹窗 | 独占视口的重任务 |
| Toast | 轻提示 | 吐司、顶部提示条、message | 弹窗 | 纯文本、自动消失 |
| Snackbar | 消息条 | 底部提示、可撤销提示 | 吐司 | 轻反馈 **+ 一个动作** |
| Notification | 通知提醒框 | 右上角通知 | 弹窗 | 与当前操作无关的异步消息 |
| Alert | 警告提示 / 内嵌提示 | 黄条、红条、提示条 | 弹窗 | 页面/区域内持续成立 |
| Inline Alert / Field Error | 行内报错 / 字段错误 | 红字、下面那行小字 | 提示 | 绑定输入框，改对才能走 |
| Banner | 横幅通告 | 顶部公告条 | Alert | 整页级、可关闭且记住 |
| Progress | 进度反馈 | 进度条 | 加载 | 有已知总量 |
| Skeleton | 骨架屏 | 占位灰块 | 加载 | 内容形状占位 |
| Spinner / Loading | 加载中 | 转圈 | 进度条 | 无已知总量 |
| Backdrop / Scrim | 遮罩层 | 蒙层、黑底 | 弹窗 | 点它能不能关，是策略不是默认 |
| Detent / Snap point | 档位 | 高度档 | — | Sheet 的 30/60/80 |
| Undo | 撤销 | 回退、恢复 | 取消 | 撤销=反悔已发生的；取消=不执行 |
| Soft delete | 软删除 | 逻辑删除、进回收站 | — | 撤销能力的工程前提 |

## 2. 描述需求时的四要素

说清这四格，AI/同事就不会猜错：

> **形态**（哪一类）+ **内容归属**（绑定哪个对象）+ **关闭策略**（背景/Esc/自动消失）+ **危险档**（如涉及写操作）

### 模板

```
这里用 <形态>，<位置/档位>，<关闭策略>；
里面是 <内容>，来自 <触发点>；
<如果是写操作> 这是 <可撤销 / 不可逆> 操作，用 <Snackbar+撤销 / Popconfirm / AlertDialog>。
```

### 例子

- 「这里用 **Bottom Sheet**，半屏档（约 60%），可上拖到 90%，点背景关闭，下滑关闭；里面是只读详情，不需要确认。」
- 「删除这一行**不要弹确认**，直接删 + 底部 **Snackbar 带【撤销】**，保留 7 秒，鼠标移上去不消失。」
- 「清空整个工作区是**不可逆**的，用 **AlertDialog**：标题写后果、正文写影响条数、主按钮红色写『永久删除 128 条』、点背景关不掉、Esc 等于取消、初始焦点在取消。」
- 「表单提交失败**不要用 toast**，错误要留在出错的字段**下方**，不自动消失，并滚动到第一个错误字段。」
- 「这个图标按钮没有文字标签，加 **Tooltip** 说明它是什么；触屏上把同样的文字放到按钮下方的常驻标签里。」
- 「导出是长任务：点击后给 **Toast**『已开始导出』，完成后走 **Notification** 带下载链接，进度用 **Progress** 且可取消。」

## 3. 让 AI 评审现有界面

```
按「打断强度 0–5」给我这个页面上每一条反馈定级，指出：
1) 有没有用 toast 承载必须看到的错误；
2) 有没有可撤销操作被做成了确认框（或反过来，不可逆操作只给了 toast）；
3) 每个浮层的 scrim / Esc / 自动消失策略分别是什么，哪些不符合「Esc 永远等于取消」「危险确认禁点背景」；
4) 移动端从属任务有没有被做成居中弹窗或窄屏抽屉；
5) 行内报错会不会自动消失。
只报缺陷与证据位置，不要顺手改风格。
```

## 4. 让 AI 整改一个仓库

```
先取基线再动手，不要一次改全仓：
1) 数一下有几套 toast、多少处原生 confirm()/alert()、关闭策略有没有显式约定、有没有统一危险入口、行内报错走不走 toast、移动端有没有 sheet 分档；把读数列成表。
2) 只做 T<档号> 这一档（T1 清原生对话框 / T2 统一危险入口 / T3 轻反馈归一 / T4 行内报错归位 / T5 关闭策略显式化 / T6 撤销链路 / T7 移动端形态 / T8 层级收敛）。
3) 档位阈值要落成一个可被调用的判定函数，不要在文档里写死而各页自判。
4) 改完给我可复现的验证方式（契约测试或探针命令），并给出改前/改后读数。
```

## 5. 常见模糊说法 → 精确说法

| 会被猜错的说法 | 猜错的后果 | 换成 |
|---|---|---|
| 「加个弹窗提示一下」 | 得到居中 Modal，用户每删一行都要点一次 | 「保存成功给 4 秒 Toast」/「删除给 Snackbar + 撤销」 |
| 「删除要确认一下」 | 得到可点背景关闭、主按钮写「确定」、焦点在确定的 AlertDialog | 「这是不可逆删除，用 AlertDialog：禁点背景、Esc=取消、主按钮写『永久删除 N 条』、焦点在取消」 |
| 「报错提示出来」 | 得到 5 秒 toast，用户抬头时错误没了、表单还在 | 「字段错误显示在输入框下方，不自动消失，提交失败滚动到第一个错误」 |
| 「这里做个抽屉」 | 手机上得到 320px 宽的侧边抽屉或失控全屏 | 「桌面用右侧 Drawer（480px），移动端用 Bottom Sheet 半屏档」 |
| 「弹个提示让用户撤销」 | 得到没有软删除支撑的假撤销按钮 | 「删除走软删除，保留 7 秒可撤销，回收站保留 30 天，删除与撤销都入审计留痕」 |
| 「加个 loading」 | 得到整页遮罩转圈 | 「首屏用 Skeleton 保留布局；提交按钮内用 Spinner + 文案『保存中…』并禁用该按钮」 |
| 「这个按钮加个说明」 | 得到触屏上永远看不到的 Tooltip | 「图标按钮加 Tooltip，同时在详情页里常驻同一句说明」 |
